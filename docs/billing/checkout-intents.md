# 首次付款前的账户级结账占位

同一账号跨 Creem、PayPal、Waffo 最多保留一次未解决的结账尝试。同渠道同套餐重试返回原结账；切换渠道或套餐须先确认旧结账及其订单不可继续付款。浏览器返回、页面关闭和本地超时都不释放占位，也不授予权益。

## 创建与查询

`POST /api/billing/subscriptions/create` 仍接受 `{ provider, tier }`，成功仍返回 `{ provider, checkoutId, checkoutUrl }`。冲突返回 HTTP 409 和 `{ error, code, pendingCheckout: { provider, tier } }`；结账地址只返回给当前登录账号，不写日志。

`billing_subscription_intents.user_id` 主键决定唯一创建者。只有成功插入或通过旧 `attempt_id`、旧状态完成条件轮换的请求可以调用渠道。取得占位后重新检查已有订阅和已付权益；保存结账结果后才向浏览器返回地址。渠道创建引用统一来自持久化的 `attempt_id`，不依赖 Creem 的 `request_id` 提供幂等。

| 状态        | 行为与恢复                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------ |
| `CREATING`  | 创建请求尚未完成；其他请求等待，不按时间释放。进程中断后由支持人员核对。                         |
| `READY`     | 已保存渠道结账；查询确认仍待付款后，同渠道同套餐复用原地址。                                     |
| `UNKNOWN`   | 渠道请求可能成功，但响应、保存或历史证据不完整。已知结账 ID 时只查询原结账；无法确认时联系支持。 |
| `COMPLETED` | 同一渠道订阅的付款已落库；再次购买仍必须通过已有订阅及已付周期检查。                             |
| `CLOSED`    | 请求尚未发出即失败，或渠道确认旧结账不可再付款；允许通过条件更新开启新尝试。                     |

PayPal 在发送创建订阅的 HTTP 请求前标记已发出；Creem 和 Waffo 在进入创建 SDK 调用前标记。SDK 内部校验或 Waffo 会话令牌步骤失败时，也可能保守保留 `UNKNOWN`。不自动重发任何结果不明的创建请求，避免依赖渠道幂等保留窗口。

Creem 仅远端 `expired` 视为关闭。PayPal 的待批准、已批准分别视为待付款、处理中；取消或到期且没有历史付款证据时视为关闭，有付款证据时等待落库。Waffo 的会话有效期单独不能释放占位：已生成订单必须同时确认终态且会话已过期；会话到期而查不到订单时仍需人工核对。

已验证付款先写入 `billing_subscriptions`，再核对结账对应的渠道订阅 ID，完成占位。回调早于结账结果保存时保留占位；重复付款回调可补做收尾。收尾失败不撤回已落库权益，渠道重试或后续创建请求可继续核对。所有更新匹配 `attempt_id` 和旧状态，迟到请求不能改写新尝试。

## 支持人员恢复

1. 查询账号的 `provider`、`tier`、`attempt_id`、`status`、`checkout_id`、`expires_at`，不要在日志或公开记录中输出 `checkout_url`；Waffo 地址包含认证令牌。
2. 使用结账 ID 或创建引用，在对应环境和商户的渠道后台核对结账、生成订单及付款。没有查询到结果不等于确认创建失败；确保原请求已停止，不会迟到创建。
3. 若已有付款，按既有已验签付款和权威交易证据流程处理，不能手动将占位状态当作权益。
4. 只有取得明确证据，确认旧结账及相关订单不可继续付款，才按 `user_id`、核对时的 `attempt_id` 和旧状态条件更新为 `CLOSED`。受影响行数必须为 1；否则重新核对，不能无条件覆盖。
5. 用户回到套餐页重试，由正常接口原子开启新尝试。不删除遗留记录，不设置定时清理或按年龄释放。
