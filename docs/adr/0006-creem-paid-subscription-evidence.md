# Creem 以已付款事件确认订阅权益

Creem 接入现有渠道适配层，作为当前唯一支付渠道提供购买入口。使用官方 `creem` SDK 创建和查询结账、订阅及交易，Webhook 在项目统一入口验证原始请求签名；不额外引入 Next.js 路由工厂，避免将页面参数作为身份或权益证据。

Creem 的 `subscription.paid` 经远端核实付款、用户、产品、客户和账期后，才能首次创建或续期订阅。`subscription.active`、`checkout.completed` 和浏览器返回不写付费权益。周期末取消映射为 CANCELLED，已付权益保留至周期结束；扣款失败映射为 PAYMENT_FAILED，保留已付账期且纳入 Creem 开放订阅约束。付款恢复必须核实交易，同一期恢复不重置额度；已取消或到期记录不会被迟到付款恢复。

优惠券付款使用远端交易实付和优惠金额核实含税套餐原价；实付为零也必须具有已付款交易和渠道优惠券 ID，不能由订阅 active 或浏览器返回推断成功。首次付款保存原价、优惠金额及渠道优惠券 ID，续费逐笔核验但不覆盖首次快照；不保存或公开券码，避免将限次优惠码暴露到账户展示中。

Creem 的生产 API 在 100% 优惠券交易中可能同时返回 `amount_paid=0` 和 `discount_amount=0`。仅当远端订阅明确携带有 ID 的 100% 百分比优惠券、交易金额与远端含税产品价格及本地套餐价一致，且其余付款身份和账期证据通过时，将优惠金额规范为原价；不推算实付，不以原价减实付补齐部分优惠。携带优惠券的订阅必须有明确的 `amount_paid`，一次性优惠券保留在订阅上时，后续全价交易仍记录零优惠。
