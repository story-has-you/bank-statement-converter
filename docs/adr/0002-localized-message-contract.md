# 多语言消息与风险原因在展示层本地化

## 状态

已接受

## 决策

网站支持 `en`、`zh-CN`、`ja`、`ko`、`de`、`fr` 和 `es` 七种语言。语言代码表示界面语言，不表示国家、货币或法律管辖区。

页面之外的 API 路由不带 `[locale]` 路径，因此浏览器请求通过 `x-app-locale` 传递当前界面语言。服务端只接受已配置的语言代码；缺失或非法值回退到英文。

解析器和转换 API 使用稳定的错误码、风险码和参数，不把某一种语言的句子作为接口契约。Next.js 展示层根据当前语言渲染错误和风险原因。网页和 Excel 下载共用同一套翻译，以保持 `OK`、`DISCREPANCY` 和 `UNVERIFIABLE` 的含义一致。

## 原因

如果解析器直接返回中文或英文句子，语言切换后仍会出现混合语言，也无法保证网页和 Excel 的提示一致。稳定代码能保持接口兼容，并让每个展示端自行选择语言。

语言代码不映射国家，避免因为界面语言推断用户的税务、隐私或支付管辖区。法律页面继续使用同一套内容，并保留“按适用法律”的表述。
