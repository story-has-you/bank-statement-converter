# 计费流程与支付渠道适配器分离

网站订阅资格、权益、状态同步和数据库写入由通用计费模块持有，渠道以函数式适配器负责 SDK、配置、验签、远端查询和付款证据校验。适配器先验签并输出标准化通知，再按需核实远端证据形成项目自己的订阅快照及激活、取消、续费事件，不直接访问 Supabase；当前只实现 PayPal，以便接入其他渠道时复用现有业务规则。

订阅引用由支付渠道和渠道订阅 ID 共同确定，用户最多一条开放订阅的限制仍跨渠道生效。只有已验签且经远端核实的激活事件可以创建首条记录；前端批准不能授予权益，取消与续费保留现有幂等、乱序及并发保护。

旧 PayPal 路由保留为共享处理函数的兼容入口。数据库列重命名采用一次协调切换，避免新增双写、临时兼容列或数据库业务函数；切换期间必须停止全部计费依赖请求并让回调返回可重试错误。执行步骤见 [计费切换与验收](../billing-provider-cutover.md)。

非首次激活的已处理事件在验签后按本地事件版本忽略，再决定是否查询远端；避免重复取消回调在远端后续变为其他终态时误报失败。
