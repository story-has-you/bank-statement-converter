# 计费流程与支付渠道适配器分离

网站订阅资格、权益、状态同步和数据库写入由通用计费模块持有，渠道以函数式适配器负责 SDK 或 REST API、配置、验签、远端查询和付款证据校验。适配器先验签并输出标准化通知，再按需核实远端证据形成项目自己的订阅快照及激活、取消、续费事件，不直接访问 Supabase；当前支持 Creem、PayPal 和 Waffo。

订阅引用由支付渠道和渠道订阅 ID 共同确定，每个用户跨渠道最多一条开放订阅。只有已验签且经远端核实的付款事件可以创建首条记录；前端批准不能授予权益，取消与续费保留现有幂等、乱序及并发保护。

统一计费接口按渠道注册分发，`handleSubscriptionRequest` 不包含渠道专属逻辑。三个渠道复用跳转结账，PayPal 使用服务端 REST API，Waffo 使用服务端官方 SDK，不引入浏览器支付 SDK。历史数据库迁移保留，新增迁移扩展跨渠道开放订阅约束；执行步骤见 [计费切换与验收](../billing/billing-provider-cutover.md)。

非首次激活的已处理事件在验签后按本地事件版本忽略，再决定是否查询远端；避免重复取消回调在远端后续变为其他终态时误报失败。

Waffo 撤销周期末取消输出独立的恢复事件，必须核实已有付款及相同账期后才恢复 ACTIVE，不允许普通付款事件撤销取消。当前价为税前价，渠道实付必须与税额闭合；详见 [Waffo 测试支付接入](../billing/waffo-billing.md)。
